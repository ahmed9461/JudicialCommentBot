# الفهرس القضائي الرسمي — Official Judicial Catalog

## القرار المعماري

البحث عبر نموذج لغوي ليس بوابة إلزامية لاختيار القضية. المسار الأساسي للمشروع هو فهرس محلي دائم مبني من ملفات الأحكام والمدونات المنشورة لدى الجهات الرسمية. البحث عبر DeepSeek يبقى خياراً احتياطياً فقط عندما لا يوفر الفهرس عدداً كافياً من المرشحين.

الهدف هو حل ثلاث مشكلات جوهرية:

1. عدم دفع تكلفة بحث ويب في كل طلب.
2. عدم الاعتماد على قدرة نموذج لغوي على اكتشاف رابط PDF رسمي مباشر في كل مرة.
3. ضمان أن المرشح يبدأ أصلاً من ملف رسمي معروف يمكن تنزيله والتحقق منه واستخراج صفحاته دون إعادة إنشاء المحتوى.

## التدفق

Official source manifest -> Download official PDF -> Parse pages -> Detect conservative case boundaries -> Local SQLite catalog -> Subject-aware deterministic retrieval -> Existing PDF verification/deduplication -> Ranking -> Commentary -> DOCX

إذا أعاد الفهرس أقل من العدد المطلوب:

Local catalog -> bounded DeepSeek web fallback -> official PDF verification -> merge -> ranking

## تغطية جميع المقررات

لا يوجد منطق خاص بمقرر واحد داخل كود الفهرس. جميع المقررات الـ34 تمر عبر `CatalogResearchProvider` نفسه.

تخصيص كل مقرر يأتي من مصدرين قابلين للتحرير:

- `knowledge/subjects/<slug>.yaml`: الموضوعات، كلمات البحث، الأنماط المناسبة، ومحاور التعليق.
- `config/subject_source_map.yaml`: الجهات الرسمية المفضلة لكل مقرر.

بهذا يمكن إضافة مقرر أو تعديل معرفته دون تعديل محرك البحث.

## مصادر الفهرسة

`config/catalog_sources.yaml` هو سجل المصادر القابلة للفهرسة. يدعم حالياً:

- مجموعات وزارة العدل الرسمية لعام 1434هـ.
- مجموعات وزارة العدل الرسمية لعام 1435هـ.
- مدونات ديوان المظالم عبر صفحة المدونات القضائية الرسمية.
- مدونات قرارات الأمانة العامة للجان الزكوية والضريبية والجمركية.
- صفحات القرارات والمبادئ الرسمية للجان الفصل في منازعات الأوراق المالية.

يمكن إضافة مصدر جديد من `source_registry.yaml` إلى manifest دون تغيير منطق الاختيار.

## قواعد الأصالة

الفهرسة لا تجعل القضية معتمدة تلقائياً. كل قضية مختارة تمر لاحقاً من طبقة PDF الحالية كاملة:

- النطاق رسمي ومسموح.
- HTTPS وتحويلات آمنة.
- Magic bytes وبنية PDF.
- SHA-256.
- استخراج صفحات القضية مباشرة من الملف الرسمي عند كونها جزءاً من مجموعة.
- التحقق من رقم القضية داخل الصفحات المستخرجة.
- منع التكرار والحجز.

الفهرس لا ينشئ PDF ولا يعيد كتابة الحكم.

## بناء الفهرس

```bash
python -m app.catalog refresh
```

عرض الحالة:

```bash
python -m app.catalog stats
```

فهرسة مصدر واحد أثناء الاختبار:

```bash
python -m app.catalog refresh --source moj_1435 --max-documents 2
```

إعادة فهرسة الملفات الموجودة عمداً بعد تغيير خوارزمية الاستخراج:

```bash
python -m app.catalog refresh --force
```

التحديث العادي incremental: الملفات الرسمية التي سبق فهرستها تُتجاوز، بينما crawler يكتشف ملفات جديدة. لذلك المؤقت الأسبوعي لا يعيد تنزيل كل الأرشيف كل مرة.

## أوامر المالك

`/catalog` يعرض عدد القضايا والمجموعات والجهات المفهرسة.

## دور DeepSeek بعد هذا التغيير

DeepSeek لا يُستخدم لفهرسة الملفات الرسمية نفسها. دوره:

1. fallback محدود لاكتشاف قضية عندما يكون الكتالوج ناقصاً.
2. التحليل القانوني وكتابة التعليق بعد التحقق من الحكم.

بهذا يصبح استخدام الذكاء الاصطناعي في النقاط التي يحتاج فيها المشروع إلى فهم دلالي، وليس في عمل فهرسة أرشيفية يمكن تنفيذه مرة واحدة وإعادة استخدامه.
