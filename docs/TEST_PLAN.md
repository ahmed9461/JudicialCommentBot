# خطة الاختبارات

## Unit Tests

### Authorization

- المالك مسموح دائماً.
- مستخدم allowlist مسموح بالمهام العادية.
- مستخدم غير مصرح مرفوض.
- مستخدم allowlist لا يستطيع أوامر إدارة المستخدمين.

### Knowledge

- كل slug في index له ملف موجود.
- لا توجد slugs مكررة.
- كل YAML يمر schema validation.
- priority_topics غير فارغة.

### Scoring

- مجموع الأوزان = 100.
- قضية مباشرة الصلة تتفوق على قضية بعلاقة بعيدة.
- فشل PDF يمنع الاعتماد مهما كانت درجة المحتوى.
- تحت العتبة ينتقل التدفق إلى top 3.

### Duplicate Detection

- نفس رقم القضية والمحكمة = مكرر.
- نفس SHA-256 = مكرر ولو اختلف الرابط.
- رابط مختلف لا يعني قضية مختلفة.
- أرقام متشابهة بمحاكم مختلفة لا تدمج تلقائياً.

### PDF

- ملف يبدأ `%PDF-` ويفتح ينجح تقنياً.
- HTML متنكر كـ PDF يفشل.
- حجم زائد يفشل.
- redirect إلى شبكة داخلية يفشل.
- extract من مجموعة رسمية يسجل صفحات المصدر.

### Commentary Validator

- `##` يفشل.
- `**` يفشل.
- DeepSeek/ChatGPT/ذكاء اصطناعي يفشل.
- قسم مفقود يفشل.
- رقم قضية خاطئ يفشل.
- تعليق صحيح ينجح.

### Cleanup

- الملفات تحذف بعد نجاح الإرسال.
- عند فشل Telegram تبقى حتى تنتهي سياسة retry ثم تنظف.
- cleanup لا يحذف ملفات خارج Job directory.

## Integration Tests

- مسار كامل بمرشحين محليين وPDF fixtures.
- أفضل قضية تفشل PDF ثم ينتقل للثانية.
- أعلى قضية >=90 تعتمد تلقائياً.
- درجات متقاربة تعرض 3 خيارات.
- إعادة التوليد لا تسجل CaseUsage جديداً.
- قضية أخرى تستبعد القضية الحالية.

## No-live-network CI

معظم CI يجب أن يعمل بدون الإنترنت باستخدام fixtures وmock adapters. اختبارات المصادر الحية تكون منفصلة واختيارية حتى لا تصبح CI رهينة مواقع خارجية.
