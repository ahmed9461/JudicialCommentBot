# قواعد التحقق

## CaseIntegrityValidator

يتحقق من:

- رقم القضية قابل للتطبيع وغير فارغ عندما يكون منشوراً.
- المحكمة معروفة أو موصوفة بوضوح.
- بيانات الاستئناف لا تختلط ببيانات الدرجة الأولى.
- عنوان القضية ليس استنتاجاً يناقض موضوع الحكم.

## OriginalPdfValidator

- الملف PDF حقيقي.
- المصدر يطابق سياسة الثقة.
- البصمة محسوبة.
- لا يوجد دليل أنه ملف معاد إنشاؤه بواسطة النظام.
- عند extract: المصدر مجموعة رسمية وصفحات الأصل مسجلة.

## DuplicateCaseValidator

يستعمل بالتتابع:

1. case number + normalized court.
2. judgment/deed number إن وجد.
3. SHA-256.
4. تشابه بيانات القضية كإشارة مراجعة لا كقرار وحيد.

## CommentaryContentValidator

يفشل الملف إذا وجد:

- Markdown واضح.
- ذكر لأدوات AI أو البوت.
- placeholders داخل متن التعليق غير مقصودة.
- أقسام أساسية مفقودة.
- رقم قضية أو محكمة لا تطابق بيانات القضية.
- نصوص مثل "لا أستطيع" أو تعليمات للنموذج.

ويتحقق أيضاً من:

- وجود ربط فعلي بالمادة.
- وجود رأي مبرر.
- عدم تكرار فقرة أو جملة بشكل آلي واضح.

## DocxFormattingValidator

- RTL للفقرات العربية.
- العناوين مميزة بأسلوب Word لا Markdown.
- لا يوجد overflow أو صفحات فارغة غير مقصودة.
- أسماء الملفات آمنة ومفهومة.

## قرار الإرسال

لا يُرسل أي ناتج إذا فشل Validator حرج. يعاد التوليد أو البحث بحسب نوع الفشل، مع حد للمحاولات حتى لا يدخل النظام في حلقة لا نهائية.
